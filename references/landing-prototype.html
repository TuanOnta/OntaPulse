How it works

From request to result, without blocking.

Triggering a scan never makes you wait on the target. The API queues the work and a separate worker does the check.

01

Queue

Trigger a scan or let the interval do it. The API records it as queued and answers right away.

02

Check

A worker picks up the job, confirms the target is public, and sends an HTTP GET with strict timeouts.

03

Review

Status and findings land in your workspace for everyone on the team to see.

Scan results

Every scan tells you what happened.

A target that answers with an error is still a result worth reading. OntaPulse keeps the scan, records the response time, and turns problems into findings with a severity.

Timeouts and DNS failures are recorded as failed scans, so you can tell an unhealthy page from an unreachable one.

Features

Built for teams that share one source of truth.

Workspaces and roles

Owner, Admin, and Member roles per workspace. Everyone sees the results; only the right people change things.

Projects and monitors

Group HTTP and HTTPS targets into projects and set an interval from one minute up to a full day.

Findings that matter

Client errors, server errors, and slow responses become structured findings, each with a severity.

Safe by design

Targets must resolve to public addresses and redirects are not followed, so a check can't be steered into a private network.

Resilient checks

When infrastructure hiccups, a job retries after 5, 30, and 120 seconds before it is set aside for review instead of vanishing.

Made for teams

Add registered teammates, adjust their roles, and review every scan together in one place.
